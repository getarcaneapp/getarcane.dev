The `kit.getarcane.app` modules are a set of reusable Go modules for Docker tooling, root-confined
filesystem access, streaming, and system probes. They live in the
[`getarcaneapp/kit`](https://github.com/getarcaneapp/kit) repository.

Application-specific concerns such as settings, persistence, and notifications are passed in
through small interfaces, so the modules fit into any Go application.

## Module map

| Module                             | Import path                        | Use it for                                               |
| ---------------------------------- | ---------------------------------- | -------------------------------------------------------- |
| [kit](/kit/)                       | `kit.getarcane.app`                | Shared helpers, byte sizes, secret encryption            |
| [acfs](/acfs/)                     | `kit.getarcane.app/acfs`           | Filesystem access that can never escape a root directory |
| [tripwire](/tripwire/)             | `kit.getarcane.app/tripwire`       | Watching a directory tree for changes                    |
| [docker](/docker/)                 | `kit.getarcane.app/docker`         | Docker Engine helpers, old-daemon compat, live streams   |
| [docker/convert](/docker/convert/) | `kit.getarcane.app/docker/convert` | `docker run` → Compose conversion                        |
| [builds](/builds/)                 | `kit.getarcane.app/builds`         | BuildKit builds via Docker or Depot                      |
| [updater](/updater/)               | `kit.getarcane.app/updater`        | Keeping containers on current images                     |
| [sys/cgroup](/sys/cgroup/)         | `kit.getarcane.app/sys/cgroup`     | Container resource limits and identity                   |

Some pages document a package inside a module rather than a module of its own:
[sys/bytes](/sys/bytes/) and [sys/crypto](/sys/crypto/) are in `kit`, and
[docker/compat](/docker/compat/) and [docker/streams](/docker/streams/) are in `docker`. Each
page shows the module to `go get`.

## Moving from go.getarcane.app

The modules used to be served from `go.getarcane.app`. Versions published there keep working, but
new releases are only on `kit.getarcane.app`. Rewrite your imports:

| Old import path                  | New import path                          |
| -------------------------------- | ---------------------------------------- |
| `go.getarcane.app/kit/pkg`       | `kit.getarcane.app`                      |
| `go.getarcane.app/kit/pkg/<pkg>` | `kit.getarcane.app/<pkg>`                |
| `go.getarcane.app/kit/<pkg>`     | `kit.getarcane.app/<pkg>`                |
| `go.getarcane.app/sys/bytes`     | `kit.getarcane.app/sys/bytes`            |
| `go.getarcane.app/sys/crypto`    | `kit.getarcane.app/sys/crypto`           |
| `go.getarcane.app/acfs/atomic`   | `kit.getarcane.app/fs/atomic`            |
| `go.getarcane.app/docker/compat` | `kit.getarcane.app/docker/compat`        |
| `go.getarcane.app/streams/<pkg>` | `kit.getarcane.app/docker/streams/<pkg>` |
| `go.getarcane.app/<module>`      | `kit.getarcane.app/<module>`             |

## How the repository is laid out

Every module is a directory in the repository with its own `go.mod`. The root `kit` module lives
in `kit/`:

- Modules may import `kit`. `kit` never imports another module.
- Code only moves into `kit` once it has a concrete contract that more than one module needs.
- Each module is tagged independently, for example `kit/v0.5.0` or `updater/v0.12.0`.

## Stability

:::caution
Every module is below v1.0.0. Under Go's module rules, minor releases (`v0.x.0`) can contain
breaking API changes. Pin versions in `go.mod` and read each module's `CHANGELOG.md` before you
upgrade.
:::
